# Comment Discipline

- Default to writing no comments.
- Add a comment only when the why, invariant, tradeoff, or hazard is non-obvious from the code itself.
- Do not explain what the code does when names and structure already make that clear.
- If the code needs narration to be understandable, improve the code before adding commentary.
